# Tested browser-agent behavior

## Current native WebMCP and live-data run

On September 3, 2026, the production Label Relay client was run in Chrome `151.0.7922.173` with the WebMCP testing feature enabled. The application loaded actual Open Food Facts network data for Quaker Old Fashioned Oats and registered all eight production tools through the current `document.modelContext` surface.

The run verified:

- `document.modelContext` and its testing surface were present;
- eight closed-schema tools registered;
- `lookup_barcode` returned the actual Open Food Facts record and updated the visible page;
- `stage_verified_choice` staged that same record;
- two `record_package_check` calls produced pending attestations and cleared no requirements;
- two trusted visible **Confirm I said this** clicks cleared the corresponding requirements;
- a trusted visible approval unlocked the verified-label summary;
- `get_approved_choice` returned the same summary shown in the page;
- a later confirmed mismatch revoked approval and exposed the exact Open Food Facts correction URL;
- no browser console errors occurred.

The recorded source data included:

- browser: Chrome `151.0.7922.173`;
- source: Open Food Facts;
- product ID: `0030000010402`;
- product: Old Fashioned Oats by Quaker Oats;
- source fetch time: `2026-09-03T15:45:25.824Z`;
- upstream modification time: `2026-08-10T16:11:39.000Z`;
- Open Food Facts completeness: `79`;
- WebMCP transport: `document.modelContext`;
- browser errors: zero.

Machine-readable evidence is committed at `docs/evidence/demo-capture-report.json`. The upload-ready screen recording was generated by `.github/workflows/demo-video.yml` from the same run.

## Deterministic regression runs

The repository also keeps deterministic unit and browser tests with controlled Open Food Facts-shaped responses. These cover malformed input, non-JSON upstream responses, output budgets, pending attestation behavior, rejection, approval, later mismatch invalidation, correction links, English-ingredient preference, completeness ranking, and mobile overflow.

Those tests are presented as regression tests—not as proof of live data or native WebMCP.

## Claim boundary

The Chrome 151 run proves the current native `document.modelContext` protocol and actual Open Food Facts network data together against the exact repository application on a local static server.

It does **not** prove that:

- the separate public ChatGPT Sites deployment has been refreshed to this commit;
- ChatGPT’s in-app browser has invoked the tools on that public origin;
- a public YouTube demo URL has been published.

Those remain release checks, not engineering claims.
